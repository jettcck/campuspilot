# CampusPilot 开发文档

本文档记录项目的设计思路、架构决策与开发流程，适合作为二次开发与项目答辩的参考材料。

---

## 一、需求分析

### 用户角色

| 角色 | 说明 |
| --- | --- |
| 学生（默认） | 管理自己的任务、课程、资料、计划与小组 |
| 小组管理员（组长） | 额外拥有解散小组的权限 |
| 管理员（预留） | 发布校园公告，角色通过 `role` 字段区分 |

### 核心场景

1. 学期初：把课程录进系统，拆解学习目标
2. 日常：每天勾选任务，看专注趋势
3. 复习期：上传课件，让 AI 生成摘要与自测题
4. 大作业：建小组、发邀请码、分头推进
5. 信息获取：浏览讲座与比赛通知

### MVP 边界

第一版完整实现：认证、任务、课程资料、学习计划、AI 学习室、小组、校园信息、统计。

预留扩展：消息通知、RAG 检索、移动端、多租户（校级部署）。

## 二、系统架构

```text
┌──────────────────────────────┐
│  React 18 前端（Vite 构建）   │
│  哈希路由 / Context / 图表     │
└──────────────┬───────────────┘
               │ fetch（自动附带 JWT）
┌──────────────▼───────────────┐
│  Express 应用                 │
│  routes → controllers         │
│           → services          │
│           → 数据访问层         │
└──────┬──────────┬────────────┘
       │          │
┌──────▼─────┐ ┌──▼─────────────┐
│ MongoDB /  │ │ AI Provider     │
│ 本地 JSON  │ │ OpenAI 兼容协议  │
└────────────┘ └────────────────┘
```

### 分层职责

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 路由层 | `server/routes` | 只做 URL 与中间件绑定 |
| 控制器层 | `server/controllers` | 参数校验、业务编排、组织响应 |
| 服务层 | `server/services` | 可复用的跨模块能力（AI、统计、初始化） |
| 数据访问层 | `server/utils/store.js` | 统一的集合操作接口，屏蔽存储差异 |
| 中间件层 | `server/middleware` | 鉴权、错误处理、文件上传 |

## 三、关键设计决策

### 决策 1：数据层双模式

**问题**：评审和演示环境往往没有 MongoDB，若强依赖会导致项目无法直接运行。

**方案**：`store.js` 对外暴露 `collection(name)`，返回具有 `find / findOne / findById / insert / updateById / deleteById / deleteMany / count` 的适配器对象。启动时若 `MONGODB_URI` 连接成功则返回 Mongoose 适配器，否则返回基于 `server/data/db.json` 的文件适配器。

**收益**：业务代码零改动即可在两种存储间切换；本地文件模式还实现了 `$in / $ne / $regex / $or / $gte / $lte` 等常用查询算子，与 Mongo 语义保持一致。

### 决策 2：AI 服务抽象 + 降级策略

**问题**：AI 接口需要 Key，且在演示环境可能不可用。

**方案**：`aiService` 提供 `chat / summarize / quiz / studyPlan / advise` 五个语义化方法。内部先尝试调用 OpenAI 兼容的 `/chat/completions`；失败或未配置 Key 时，回落到内置规则引擎，输出结构完全一致的结果，并在响应中用 `provider` 字段标明数据来源。

**收益**：功能链路永远可用；切换厂商只需改环境变量；答辩时可以直观演示两种模式。

### 决策 3：JWT 无状态鉴权

- 登录成功后签发 7 天有效的 Token，载荷只包含 `userId` 与 `role`
- 前端在 `localStorage` 保存，API 客户端统一注入 `Authorization` 头
- 后端 `requireAuth` 中间件解析 Token 并回查数据库，确保用户可以即时失效
- 收到 401 时客户端自动清除本地 Token，回到登录页

密码使用 bcrypt（cost=10）加盐哈希，数据库中不存明文。

### 决策 4：统一响应与错误处理

所有接口返回 `{ success, message, data, error }`。控制器通过抛出 `ApiError(status, message, code)` 表达失败，全局错误中间件统一转换成 JSON；开发环境附带 `stack` 便于排查，生产环境自动隐藏。

### 决策 5：前端极简路由

项目不需要引入 React Router：`App.jsx` 中 20 行的哈希路由 Hook 即可支持刷新、前进后退与分享链接（如 `#/courses`），同时减少依赖体积。

## 四、数据库设计

### users

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| _id | ObjectId / String | 主键 |
| username | String | 昵称 |
| email | String | 唯一索引，登录账号 |
| passwordHash | String | bcrypt 哈希，接口不返回 |
| avatar | String | 头像文字 |
| school / major / grade | String | 学校信息 |
| role | String | student / admin |
| createdAt / updatedAt | Date | 时间戳 |

### courses

`userId`（索引）、`name`、`teacher`、`semester`、`color`、`description`、`tags[String]`、`progress`、`nextClass`

### tasks

`userId`（索引）、`courseId`、`title`、`meta`、`tag`、`color`、`priority`、`status`、`done`、`dueDate`、`estimatedMinutes`

### studyplans

`userId`（索引）、`title`、`goal`、`startDate`、`endDate`、`steps[{ day, title, minutes, point, done }]`、`progress`、`status`

### groups

`name`、`description`、`ownerId`、`memberIds[String]`、`inviteCode`

### notices

`title`、`category`、`content`、`source`、`publishAt`

### files

`userId`、`courseId`、`filename`、`fileUrl`、`fileType`、`fileSize`、`extractedText`、`summary`、`tags[String]`

### aichats

`userId`、`scene`、`prompt`、`reply`

## 五、开发流程与分支规范

### 阶段划分

1. 需求分析 → 功能清单与 MVP 边界
2. 系统设计 → 架构图、数据结构、接口契约
3. 后端开发 → 数据层 → 认证 → 业务接口 → AI 服务
4. 前端开发 → API 客户端 → 登录 → 各业务页面 → 图表
5. 联调测试 → 接口验证 + 浏览器端流程验证
6. 部署上线 → Docker 镜像 → 服务器 → Nginx → HTTPS

### 分支模型

```text
main        可部署的稳定分支
develop     集成分支
feat/xxx    功能分支
fix/xxx     修复分支
```

提交信息使用 Conventional Commits：`feat: 新增小组邀请码加入`、`fix: 修复任务完成后统计未刷新`。

### 代码规范

- 前后端统一使用 ES Module
- 变量与函数使用小驼峰，常量使用大写下划线
- 代码注释使用中文，说明「为什么」而不是「做了什么」
- 不提交 `.env`、`server/data`、`uploads`、`node_modules`、`dist`

## 七、可扩展方向

1. **RAG 资料问答**：解析 PDF 文本 → 切分 → 向量化 → 检索增强后再交给模型，实现「根据我的课件回答」
2. **消息通知**：任务截止提醒、小组变更提醒，接入邮件或 Web Push
3. **权限系统升级**：从角色判断升级为 RBAC（Role → Permission → Resource）
4. **移动端**：复用现有 REST 接口，用 React Native / UniApp 扩展
5. **多租户**：按学校或院系隔离数据，支持校级部署与后台管理
6. **缓存与限流**：接入 Redis 缓存统计结果，为 AI 接口增加频率限制

## 八、常见开发问题

| 问题 | 原因与处理 |
| --- | --- |
| 前端请求 404 | 确认后端已启动，开发环境依赖 Vite 代理 `/api` |
| 接口 401 | Token 过期或 `JWT_SECRET` 变更，重新登录 |
| 数据写入后重启丢失 | 检查是否误删 `server/data/db.json` 或执行了 `docker compose down -v` |
| AI 一直返回模板文本 | 未配置 `AI_API_KEY` |
| 上传报类型不允许 | 检查 `server/middleware/upload.js` 的扩展名白名单 |
