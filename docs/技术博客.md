## 篇一：React + Express 全栈项目的分层架构该怎么拆

**背景**：学生项目最容易写成「一个文件几百行」的接口集合，后期加功能就会失控。

**做法**：把后端拆成五层，每层只做一件事。

```text
routes      只注册 URL 和中间件，不写业务
controllers 校验参数、编排流程、组织响应
services    跨模块能力（AI、统计）
utils/store 数据访问，屏蔽存储差异
middleware  鉴权、错误处理、文件上传
```

对应到目录就是 `server/routes`、`server/controllers`、`server/services`、`server/utils`、`server/middleware`。

**收益**：新增一个业务模块只需要「建模型 → 写控制器 → 注册路由」三步；接口出错时能快速定位是参数问题、业务问题还是存储问题。

**经验**：不要一开始就抽象。等到出现第二个调用方时再抽服务层，否则会为了「看起来架构好」而写出一堆空壳。

## 篇二：用 JWT 实现一个能上线的用户认证

**核心流程**：

```text
注册：密码 → bcrypt 加盐哈希 → 存库
登录：查用户 → bcrypt.compare → 签发 JWT → 返回给前端
访问：前端带 Authorization: Bearer <token> → 中间件校验 → 注入 req.user
```

**三个容易踩的坑**：

1. **JWT 里不要放敏感信息**。JWT 只是签名，不是加密，任何人都能解码看到内容。只放 `userId` 和 `role`。
2. **改密码后旧 Token 仍然有效**。解决方案是中间件校验时回查数据库确认用户存在，并在需要时引入 `tokenVersion` 字段做批量失效。
3. **前端要统一处理 401**。在 API 客户端里拦截 401，清掉本地 Token 并跳回登录页，否则用户会卡在「点啥都报错」的状态。

**代码位置**：`server/utils/security.js`、`server/middleware/auth.js`、`src/api/client.js`。

## 篇三：让项目在没有数据库时也能跑起来

**问题**：答辩现场、评审电脑、CI 环境不一定有 MongoDB，但项目演示不能因此开天窗。

**方案**：做一层数据访问适配器。

```js
// server/utils/store.js
export function collection(name) {
  return mongoReady ? mongoAdapter(name) : fileAdapter(name)
}
```

两个适配器实现完全一致的异步接口（`find / insert / updateById / deleteById / count`），业务代码只依赖接口，不依赖具体实现。

文件适配器需要自己实现查询语义，因此我实现了 `$in / $ne / $regex / $or / $gte / $lte` 等常用算子，保证和 Mongo 的行为一致。

**收益**：

- 本地开发零配置，`npm i && npm run server` 就能跑
- 生产环境填上 `MONGODB_URI` 自动切换，代码零改动
- CI 里可以直接跑冒烟测试

**代价**：文件存储不适合多进程并发写入。因此生产环境仍然推荐 MongoDB，文件模式定位为「开发与演示」。

## 篇四：AI 功能怎么接才不至于「没 Key 就瘫痪」

**思路**：把「调用模型」和「业务语义」分开。

```text
业务层：aiService.studyPlan(goal, days)
         ↓
模型层：callModel('plan', prompt)  →  OpenAI 兼容接口
         ↓ 失败 / 无 Key
兜底层：内置规则引擎，输出同结构结果
```

**关键设计**：

1. **统一协议**：只对接 OpenAI 兼容的 `/chat/completions`，于是 OpenAI、DeepSeek、通义千问兼容模式、智谱、本地 Ollama 都能用同一套代码，切换只改环境变量。
2. **语义化方法**：对外暴露 `chat / summarize / quiz / studyPlan / advise`，而不是暴露一个通用的 `completion`，业务层不需要拼 Prompt。
3. **可观测的来源标记**：响应里返回 `provider` 字段，前端能明确知道这次结果来自真实模型还是规则引擎，避免演示时被问住。
4. **结构化输出**：计划类结果要求返回 JSON 结构（步骤数组），兜底层直接构造同样的数组，因此前端渲染逻辑只需要一套。

**后续可扩展**：接入向量检索做 RAG，把用户上传的课件切分入库，问答时先检索再生成，回答就能贴合自己的教材。

## 篇五：不引入 UI 库，如何让页面看起来不像模板

**背景**：学生项目常见的「紫蓝渐变 + 圆角卡片」一眼就能看出是模板。

**做法**：

1. **先定调性再写代码**。这个项目选的是「深色航站 + 米白工作台」：侧边栏用 `#1e2925` 深绿黑，工作区用 `#f4f6f1` 米白，强调色用一点电光柠檬绿 `#c9f36b`。整体偏冷静、专业，符合学习工具的定位。
2. **字体做对比**。正文用 Manrope，数字与标签用 DM Mono（等宽），Logo 用衬线体。等宽字体让数据区域有「仪表盘感」。
3. **用 CSS 变量统一主题**，颜色只在一处定义。
4. **细节制造质感**：卡片描边用极浅的绿灰、进度条用圆角、深色卡片里加同心圆装饰、AI 卡片里加光晕。
5. **不要满屏都是卡片**。留白、分隔线、字号层级（28 / 14 / 11 / 9px）比堆组件更能体现设计感。

**结论**：设计的差异化来自「有取舍」，不是来自组件库的丰富度。

## 篇六：把 Node 项目部署到云服务器的最短路径

**目标**：一台最便宜的云服务器、一个端口、一条命令上线。

**方案**：让 Express 同时提供 API 和前端静态资源。

```js
if (env.nodeEnv === 'production') {
  app.use(express.static('dist'))
  app.get('*', (req, res, next) => {
    if (req.path.startsWith('/api')) return next()
    res.sendFile(path.join(process.cwd(), 'dist/index.html'))
  })
}
```

于是前端请求走相对路径 `/api`，不存在跨域，也不需要单独部署前端。

**Docker 多阶段构建**：构建阶段装全部依赖并打包前端，运行阶段只保留生产依赖 + `server` + `dist`，镜像体积显著下降。

**上线三步**：

```bash
git clone <repo> && cd campuspilot
cp .env.example .env && vim .env     # 填 JWT_SECRET、MONGODB_URI、AI_API_KEY
docker compose up -d --build
```

Nginx 负责统一入口：`/uploads` 直出文件，`/api` 转发给 Node，其余交给前端。最后用 `certbot --nginx` 一行命令上 HTTPS。

**经验**：部署的复杂度主要来自「组件数量」，而不是代码量。能合并的进程就合并，学生项目优先保证「能稳定访问」。

## 篇七：项目里最值得写进简历的四个点

1. **数据层双模式**：设计统一的数据访问接口，同时支持 MongoDB 与本地文件存储，做到零配置启动、环境无感切换。
2. **AI 服务抽象**：基于 OpenAI 兼容协议封装语义化 AI 服务，支持多厂商切换，并设计规则引擎兜底，保证无 Key 环境下功能链路完整。
3. **完整的认证体系**：bcrypt 密码哈希 + JWT 无状态鉴权 + 路由级权限中间件 + 客户端 401 统一处理。
4. **工程化落地**：Docker 多阶段构建、docker-compose 编排、Nginx 反向代理、GitHub Actions 自动构建与冒烟测试。

**面试时怎么讲**：不要只讲「用了什么」，要讲「遇到了什么问题、为什么这么选、代价是什么」。例如讲数据层双模式时，要说明文件存储不适合并发写入，因此生产环境仍然推荐 MongoDB —— 这体现的是技术判断，不是堆技术栈。
