## P4 · 技术选型与理由

**页面内容**

| 层次 | 选型 | 为什么选它 |
| --- | --- | --- |
| 前端 | React 18 + Vite | 组件化便于拆分页面；生态最大，资料最多；Vite 热更新快 |
| 路由 | 自研哈希路由（20 行） | 项目规模不需要引入 React Router，20 行 Hook 反而更可控可讲 |
| 状态 | Context API | 全局只有「用户」一个共享状态，上 Redux 是过度设计 |
| 后端 | Node.js + Express | 前后端同语言，降低心智负担；中间件生态成熟 |
| 架构 | routes → controllers → services → 数据层 | 四层分离，改数据库不动业务逻辑 |
| 数据库 | MongoDB + Mongoose | 学习记录字段灵活（不同科目字段差异大），文档模型天然适配 |
| 认证 | JWT + bcryptjs | 无状态，便于水平扩展；bcrypt 自带盐，不存明文 |
| AI | OpenAI 兼容协议 | 一套代码适配 DeepSeek / 通义千问 / 智谱 / Kimi / OpenAI / Ollama |
| 部署 | Docker + Render | 多阶段构建把镜像压到最小；云平台按镜像直出，无需运维 |

**讲解重点**：**每一处选型都对应 P3 的一条非功能需求。**

**讲稿**（50 秒）

> 技术选型我坚持一个原则：**不为炫技而选，为需求而选**。
> 前端用 React 加 Vite，生态大、上手快。这里有个细节——我**没有用 React Router**，因为项目只有 8 个页面，我自研了一个 20 行的哈希路由 Hook，够用，而且能把路由原理讲清楚。同样，状态管理只用了 Context，因为全局共享状态只有一个「当前用户」，上 Redux 属于过度设计。
> 后端用 Express，四层架构：路由、控制器、服务、数据层。这样换数据库不用动业务代码。
> 数据库选 MongoDB，因为学习记录的字段是灵活的——有的课有实验分，有的课没有，文档模型天然适配。
> AI 这块我抽象成了 OpenAI 兼容协议，一套代码可以切换 DeepSeek、通义千问、智谱、Kimi，甚至本地 Ollama。
> **你会发现每一处选型都能对应到刚才的某条非功能需求。**

## P6 · 数据库设计

**页面内容**（8 个集合 + 关键设计）

| 集合 | 用途 | 关键字段 |
| --- | --- | --- |
| `users` | 用户 | email(唯一)、passwordHash、username、college |
| `courses` | 课程 | userId、name、teacher、credits |
| `tasks` | 任务 | userId、title、status、dueDate、source |
| `studyplans` | 学习计划 | userId、goal、steps[]、progress |
| `groups` | 小组 | name、inviteCode、members[]、ownerId |
| `notices` | 校园公告 | category、title、content |
| `files` | 课程资料 | courseId、originalName、size、summary |
| `aichats` | AI 对话历史 | userId、scene、prompt、reply |

**三个设计决策**

```
① 统一用 userId 做数据隔离，所有查询强制带用户条件，杜绝越权读取
② 密码只存 bcrypt 哈希，serialize 层统一剔除 passwordHash，永不外泄
③ 计划步骤 steps 内嵌数组而非独立集合——步骤永远跟随计划，不需要跨文档查询
```

**讲稿**（40 秒）

> 数据库有 8 个集合。我只讲三个设计决策。
> **第一，数据隔离**。所有属于用户的资源都带 `userId`，所有查询强制拼上用户条件。这样即使有人手动构造请求去猜别人的任务 ID，也拿不到数据。
> **第二，密码安全**。数据库里只存 bcrypt 哈希，并且我在序列化层统一剔除 `passwordHash` 字段——**即使某天有人漏写了过滤，这个字段也出不了接口**。这是纵深防御的思路。
> **第三，内嵌还是关联**。学习计划的步骤我没有做成独立集合，而是内嵌数组。因为步骤永远跟着计划走，不需要跨文档查询，内嵌更快也更简单。**MongoDB 的建模原则就是「一起访问的数据放在一起」。**

## P7 · 用户认证设计

**页面内容**（流程图）

```
注册                            登录
 │                              │
 ├─ bcrypt 加盐哈希              ├─ 取出 passwordHash
 ├─ 写入 users                  ├─ bcrypt.compare 比对
 └─ 签发 JWT                    └─ 签发 JWT
                                    │
                        ┌───────────▼───────────┐
                        │ 前端存 Token 于 localStorage │
                        │ 每次请求带 Authorization 头  │
                        └───────────┬───────────┘
                                    │
                     ┌──────────────▼──────────────┐
                     │ Express 鉴权中间件           │
                     │ requireAuth / optionalAuth  │
                     │ / requireRole               │
                     └─────────────────────────────┘
```

**三重中间件**

| 中间件 | 作用 |
| --- | --- |
| `requireAuth` | 必须登录，未登录返回 401 |
| `optionalAuth` | 登录与否都能访问，但登录后能看到自己的数据 |
| `requireRole` | 角色控制（如教师可发布公告） |

**讲稿**（40 秒）

> 认证这块是**无状态 JWT** 方案。
> 注册时密码经过 bcrypt 加盐哈希后落库，验证码不存明文。登录成功后签发 Token，前端存在 localStorage，每次请求通过 `Authorization` 头带上。
> 后端我做了三重中间件：`requireAuth` 强制登录，`optionalAuth` 允许游客访问但登录后能看到自己的数据，`requireRole` 做角色控制。**它们是路由级挂载的，不是全局的**——每个接口按需选择，避免了一刀切。
> 选 JWT 而不是 Session，是因为它无状态，将来要多开几台服务器做负载均衡时，不需要考虑 Session 共享。

## P13 · 技术难点与解决

**页面内容**（三个真实难题，这是答辩最容易被追问的部分）

### 难点一：存储层的双模式兼容

**问题**：要求「没配数据库也能跑」，但文件存储和 MongoDB 的查询语义不一致——Mongo 支持 `$in`、`$regex`、`$gte`，JSON 文件没有。
**解决**：写存储适配器，在文件模式下**自研实现了同名算子**，保证上层调用语义完全一致。
**价值**：业务代码只写一次，两种存储通用。

### 难点二：AI 输出的结构化

**问题**：学习计划需要一个**步骤数组**，但大模型返回的是 **Markdown 文本**。前端对它调 `.map()` 直接抛错，**整个页面白屏**。
**排查**：这个 Bug 在开发期完全测不出来——因为没有 Key 时走的是模板分支，永远返回数组。**接入真实模型的那一刻才引爆。**
**解决**：服务端强制模型输出 JSON 并做容错解析（兼容 ```json 包裹、字段缺失），解析失败退回模板；同时在前端加数组守卫，即使接口异常也只是显示空列表，不会整页崩溃。
**价值**：**对外部依赖的输出不能信任，必须做契约校验。**

### 难点三：容器化部署的端口陷阱

**问题**：Dockerfile 里健康检查把端口写死成 `3001`，但云平台会注入自己的 `PORT`（10000）。平台若采信这个检查，容器会被判为不健康，**部署直接失败**。
**解决**：健康检查改用 `${PORT}` 变量，并把启动等待期从 10 秒放宽到 30 秒——因为容器启动时要连远程 Atlas，预留时间不足会误判。

**讲稿**（70 秒）

> 这一页是三个真实踩过的坑，我觉得比功能本身更能说明问题。
> **第一个，存储双模式**。我要求项目「没配数据库也能跑」，但文件存储和 MongoDB 的查询语法不一样。我的做法是写适配器，在文件模式下把 Mongo 那几个算子（`$in`、`$regex`、范围查询）**自己实现了一遍**，保证上层调用完全一致。
> **第二个，我要重点讲**。学习计划需要返回一个步骤数组，但大模型给的是 Markdown 文本。前端对它调 `.map()` 直接抛异常，**整个页面白屏**。
> 这个 Bug 最麻烦的地方在于——**开发期完全测不出来**。因为没配 Key 时走的是内置模板分支，永远返回数组。**直到我接入真实模型的那一刻它才引爆。**
> 修复分两层：服务端强制模型输出 JSON 并做容错解析，解析失败退回模板；前端加数组守卫，接口异常也只是空列表而不是整页崩。
> 这件事让我明白一个道理：**对外部依赖的输出不能信任，必须做契约校验。**
> **第三个是容器化的坑**。健康检查写死了端口，而云平台会注入自己的端口，如果不改，部署会直接失败。这个是靠 CI 和线上日志发现的。

## 附一 · 常见提问预案

**Q1：为什么不用 TypeScript？**
A：这是一个取舍。项目定位是「适合编程基础中等的大学生理解和实现」，TypeScript 会引入类型体操、编译配置、第三方类型定义等额外门槛。我用的是**运行时契约校验**代替部分类型保护——比如接口层的参数校验、`serialize` 统一剔除敏感字段。如果是团队协作的中大型项目，我会推荐上 TypeScript。

**Q2：JWT 存在 localStorage 有 XSS 风险，为什么不用 httpOnly Cookie？**
A：这是真实权衡。localStorage 确实能被 XSS 读取，但 httpOnly Cookie 需要处理 CSRF，而且前后端分离部署时跨域 Cookie 更复杂。我的判断是这个项目的数据敏感度不高（学习记录），且前端没有渲染用户输入 HTML 的地方。如果要提升，方案是改用 httpOnly + SameSite=Strict，并加 CSRF Token。

**Q3：AI 返回的内容不准确怎么办？**
A：两点。第一，AI 只做**辅助生成**，学习计划生成后用户仍可手动增删改；第二，我要求模型输出结构化 JSON 并做了解析容错，**解析失败会退回本地模板**。所以最坏情况下用户拿到的仍是可用的计划，不会拿到坏数据导致页面崩。

**Q4：39 个接口都在一个路由文件里，会不会太乱？**
A：目前 39 个接口集中在一个文件，优点是**一眼看全所有 API**。当接口数超过 100 个时，我会按业务域拆成 `auth.js`、`task.js`、`course.js` 等模块。这个项目目前规模还用不上，属于有意识地控制在简单范围内。

**Q5：为什么没写单元测试？**
A：这是个真实的短板。我目前的验证方式是**接口级端到端测试**——包括本地实测、线上实测、以及用内存数据库验证 MongoDB 路径。这种方式能覆盖真实调用链，但不如单元测试精准。如果要补，我会优先给 `statsService` 的聚合逻辑和 `store` 的文件查询算子写单测，因为这两处逻辑最绕、最容易出错。

**Q6：项目最大的技术难点是什么？**
A：见 P13 的第二个——AI 输出的结构化。它的难不在于写代码，而在于**排查**。因为 Bug 只在接入真实模型后才出现，而开发期一直是模板分支，连本地复现都做不到。最后是靠线上实测才暴露的。

**Q7：为什么选 MongoDB 而不是 MySQL？**
A：因为学习记录这类数据的**字段是高度可变的**——有的课程有实验分、有的有分组、有的有考勤，用关系表要么大量空列，要么拆一堆关联表。文档模型天然适配。另外 `studyplans.steps` 这种「永远一起访问」的数据内嵌数组，比关联查询高效得多。当然用户和课程这种强关系数据，用关系库也完全合适。

**Q8：线上是免费实例，休眠了怎么办？**
A：Render 免费实例闲置 15 分钟会休眠，首次访问冷启动 30–60 秒。这是免费的代价，我把它写进了 README 说明。演示前我会提前预热。如果需要常驻，升级到 Starter 计划（$7/月）即可，**代码和配置一行都不用改**。

**Q9：如果要做成真实产品，还缺什么？**
A：三块。① 数据备份与监控——现在没有错误上报和备份策略；② 上传文件持久化——免费实例磁盘是临时的，需要接对象存储（OSS / S3）；③ 合规——涉及用户数据需要隐私政策和数据保护措施。

**Q10：这个项目你独立完成了多少？**
A：全部。包括需求梳理、架构设计、前后端编码、数据库建模、39 个接口、5 份文档、Docker 容器化、CI 流水线，以及线上部署与验收。**其中 AI 结构化输出那个白屏 Bug，是我在做线上验收测试时发现的**，不是别人告诉我的。
