# CampusPilot 部署手册

本文档说明如何把 CampusPilot 部署到公网服务器，使项目可以在线访问与演示。

## 一、部署形态

项目被打包为**单进程全栈应用**：

- `NODE_ENV=production` 时，Express 同时提供 `/api` 接口与 `dist/` 前端静态资源
- 前端请求走相对路径 `/api`，无需额外配置跨域
- Nginx 作为反向代理，对外提供 80/443 端口

这样可以只买一台最便宜的云服务器就完成上线，成本最低。

## 二、准备清单

| 项目 | 说明 |
| --- | --- |
| 云服务器 | 阿里云 ECS / 腾讯云轻量应用服务器，2 核 2G 即可 |
| 操作系统 | Ubuntu 22.04 LTS |
| 数据库 | MongoDB Atlas 免费版（可选，不配置则用本地文件存储） |
| 域名 | 可选，用于 HTTPS |
| AI Key | 可选，不配置时使用内置规则引擎 |

## 三、服务器初始化

```bash
# 1. 更新系统并安装 Docker
sudo apt update && sudo apt upgrade -y
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# 2. 安装 Docker Compose 插件（新版 Docker 已内置 compose 子命令）
docker compose version

# 3. 放行端口（云厂商控制台的安全组同样需要放行 80/443）
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

## 四、上传代码

```bash
# 方式一：从 GitHub 拉取
git clone https://github.com/<你的用户名>/campuspilot.git
cd campuspilot

# 方式二：本地打包上传
tar --exclude=node_modules --exclude=dist -czf campuspilot.tar.gz .
scp campuspilot.tar.gz root@<服务器IP>:/root/
```

## 五、配置环境变量

在项目根目录创建 `.env`：

```env
NODE_ENV=production
PORT=3001
CLIENT_URL=https://<你的域名或服务器地址>
# 反向代理之后必须置为 true，否则限流会把所有请求都算到代理 IP 上
TRUST_PROXY=true

# 生产环境务必替换
JWT_SECRET=<随机生成的长字符串，可用 openssl rand -hex 32>

# 可选：MongoDB Atlas 连接串
MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/campuspilot

# 可选：AI 能力（切换厂商只改 AI_PROVIDER 一行，baseUrl/model 自动套用预设）
# 可选值：deepseek / qwen / zhipu / moonshot / openai / ollama
AI_PROVIDER=deepseek
AI_API_KEY=sk-xxxxxxxx
# 以下两项可选，留空即用预设
# AI_BASE_URL=https://api.deepseek.com/v1
# AI_MODEL=deepseek-chat
```

Key 申请入口：

| 厂商 | AI_PROVIDER | 申请地址 |
| --- | --- | --- |
| DeepSeek | `deepseek` | https://platform.deepseek.com/api_keys |
| 通义千问（阿里云百炼） | `qwen` | https://bailian.console.aliyun.com/ |
| 智谱 GLM | `zhipu` | https://open.bigmodel.cn/usercenter/apikeys |
| 月之暗面 Kimi | `moonshot` | https://platform.moonshot.cn/console/api-keys |

填好后重启服务，用自检接口确认是否真正连通：

```bash
curl http://localhost/api/ai/status
```

`mode` 为 `remote` 表示已接通；为 `remote-error` 时 `message` 会给出具体原因（Key 无效 / 余额不足 / 模型名不存在等）。

## 六、启动服务

```bash
docker compose up -d --build

# 查看状态
docker compose ps
docker compose logs -f app
```

验证：

```bash
curl http://localhost/api/health
```

浏览器访问 `http://<服务器IP>`，首次使用请点击「注册」创建账号：

```text
邮箱：你的邮箱
密码：至少 8 位
```

注册后工作台为空，总览页会提供「一键导入示例数据」入口，用于快速确认部署链路完整可用。

## 七、配置 HTTPS 强制跳转

项目提供**双层**强制跳转，任一层失效都不会放行明文请求。

### 1. Nginx 层（裸服务器部署）

`deploy/nginx.conf` 已经把 80 端口写成纯跳转、443 端口承载全部业务：

```nginx
server {
    listen 80;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }  # 保留证书续期校验
    location / { return 301 https://$host$request_uri; }
}
```

使用步骤：

```bash
# 1. 把 deploy/nginx.conf 里的 your-domain.com 全部替换为真实域名

# 2. 签发证书
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d your-domain.com
# 证书写入 /etc/letsencrypt/live/your-domain.com/，已由 docker-compose 只读挂载进容器

# 3. 重载代理
docker compose up -d --build nginx
```

### 2. 应用层（Render 等托管平台同样生效）

`server/middleware/security.js` 中的 `enforceHttps` 会读取反向代理注入的 `X-Forwarded-Proto`：当代理声明原始协议为 `http` 时返回 `301` 跳转到 HTTPS。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ENFORCE_HTTPS` | 生产环境 `true` | 置为 `false` 可关闭应用层跳转（正常情况下不需要） |

设计上刻意做了三处收敛，避免误伤：

1. **只认代理注入的头**：本地直连与 CI 的健康检查不带 `X-Forwarded-Proto`，不会被跳转
2. **探针路径豁免**：`/api/health` 与 `/api/health/ready` 始终明文可达，平台健康检查不会被 301 判为异常
3. **已声明 https 不再二次跳转**：杜绝代理与应用互相跳转形成的死循环

### 3. Hosted 平台（Render）

Render 的边缘节点默认对 `onrender.com` 域名做 HTTP→HTTPS 跳转，实测 `http://` 请求返回 `301` 指向 `https://`。应用层中间件作为第二道保险，无需额外配置。

### 4. 验证

```bash
# 明文请求应返回 301，且 Location 指向 https
curl -sI http://your-domain.com/api/health | head -3

# HTTPS 请求应返回 200
curl -s -o /dev/null -w '%{http_code}\n' https://your-domain.com/api/health/ready

# 确认 HSTS 已下发（浏览器会记住后续必须走 HTTPS）
curl -sI https://your-domain.com/ | grep -i strict-transport-security

# 模拟代理声明明文协议，应用层应返回 301（本地生产模式即可测）
curl -sI -H 'X-Forwarded-Proto: http' http://localhost:3001/api/tasks | head -3
```

### 5. HSTS 注意事项

`max-age=15552000`（180 天）一旦被浏览器记录，回退到 HTTP 会在有效期内不可访问。建议先用较短 `max-age` 验证无误后再调大；`preload` 需确认所有子域均可提供 HTTPS 后再开启。

证书自动续期由 certbot 的 systemd 定时器负责，续期后执行 `docker compose exec nginx nginx -s reload` 即可载入新证书。

## 九、常见问题

| 现象 | 排查方向 |
| --- | --- |
| 打开页面 502 | `docker compose logs app` 查看应用是否启动失败 |
| 接口返回 401 | Token 过期或 `JWT_SECRET` 被更换，重新登录即可 |
| 上传大文件失败 | 调整 `client_max_body_size` 与 `MAX_UPLOAD_SIZE` |
| 数据重启后丢失 | 未配置 `MONGODB_URI` 时数据存在容器卷 `appdata` 中，请勿执行 `docker compose down -v` |
| AI 回复是模板文本 | 未配置 `AI_API_KEY`，配置后重启即可切换为真实模型 |

## 十、零成本方案：本机 + 内网穿透

如果暂时不买服务器，可以用 Cloudflare Tunnel 把本机服务映射到公网，适合答辩演示与作品集展示。

### 1. 以生产模式启动（单进程同时提供前端与 API）

```bash
npm run build
# .env 中设置 NODE_ENV=production
npm start
# 本机访问 http://localhost:3001
```

### 2. 下载并启动隧道

```powershell
# Windows
Invoke-WebRequest -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile "$env:TEMP\cloudflared.exe"
& "$env:TEMP\cloudflared.exe" tunnel --url http://localhost:3001 --no-autoupdate
```

```bash
# Linux / macOS
curl -fsSL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o cloudflared
chmod +x cloudflared
./cloudflared tunnel --url http://localhost:3001 --no-autoupdate
```

命令输出中会出现形如 `https://xxxx-xxxx-xxxx.trycloudflare.com` 的公网地址，任何人可直接访问。

### 3. 验证

```bash
curl https://xxxx-xxxx-xxxx.trycloudflare.com/api/health
```

### 注意事项

| 事项 | 说明 |
| --- | --- |
| 地址会变 | 免费快速隧道每次重启都会生成新的随机域名，演示前记得重新获取 |
| 电脑必须开机 | 隧道依赖本机进程，关机即下线 |
| 数据库 | 数据存在本机 `server/data/db.json`，备份该文件即可迁移 |
| 稳定性 | 免费隧道无可用性保证，正式对外提供服务仍建议购买云服务器 |
| 演示完成后 | 按 Ctrl+C 关闭隧道进程，服务随即下线 |

## 十一、性能与安全建议

1. 生产环境将 `JWT_SECRET` 设置为强随机值，并定期轮换
2. 上传目录不要放在公开可执行路径下，本项目已限制文件扩展名白名单
3. 数据库开启 IP 白名单，只允许服务器访问
4. 为 Nginx 增加限流配置，防止接口被刷
5. 使用 `docker compose` 的 `restart: unless-stopped` 保证进程异常后自动拉起
