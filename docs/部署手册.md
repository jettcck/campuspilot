# CampusPilot 部署手册

本文档说明如何把 CampusPilot 部署到公网服务器，使项目可以在线访问与演示。

## 一、部署形态

项目被打包为**单进程全栈应用**：

- `NODE_ENV=production` 时，Express 同时提供 `/api` 接口与 `dist/` 前端静态资源
- 前端请求走相对路径 `/api`，无需额外配置跨域
- Nginx 作为反向代理，对外提供 80/443 端口

这样可以只买一台最便宜的云服务器就完成上线，成本最低。

## 二、准备清单

| 项目 | 说明 |
| --- | --- |
| 云服务器 | 阿里云 ECS / 腾讯云轻量应用服务器，2 核 2G 即可 |
| 操作系统 | Ubuntu 22.04 LTS |
| 数据库 | MongoDB Atlas 免费版（可选，不配置则用本地文件存储） |
| 域名 | 可选，用于 HTTPS |
| AI Key | 可选，不配置时使用内置规则引擎 |

## 三、服务器初始化

```bash
# 1. 更新系统并安装 Docker
sudo apt update && sudo apt upgrade -y
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# 2. 安装 Docker Compose 插件（新版 Docker 已内置 compose 子命令）
docker compose version

# 3. 放行端口（云厂商控制台的安全组同样需要放行 80/443）
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

## 四、上传代码

```bash
# 方式一：从 GitHub 拉取
git clone https://github.com/<你的用户名>/campuspilot.git
cd campuspilot

# 方式二：本地打包上传
tar --exclude=node_modules --exclude=dist -czf campuspilot.tar.gz .
scp campuspilot.tar.gz root@<服务器IP>:/root/
```

Windows 上也可以用现成脚本一键完成「打包 → 上传 → 远程部署」：

```powershell
# 仅 HTTP
.\deploy\upload.ps1 -Server <服务器IP> -User root

# 部署并自动签发 HTTPS 证书（域名需先解析到该服务器）
.\deploy\upload.ps1 -Server <服务器IP> -User root -Domain campus.example.com -CertEmail me@example.com
```

## 五、配置环境变量

`deploy/deploy.sh` 会在首次部署时自动生成 `.env`（含随机 `JWT_SECRET`）。下面是生成后的完整结构与可调项：

```env
NODE_ENV=production
PORT=3001
# 站点对外地址：同时作为 CORS 白名单与 HTTPS 跳转的目标
CLIENT_URL=https://campus.example.com
# 反向代理之后必须置为 true，否则限流会把所有请求都算到代理 IP 上
TRUST_PROXY=true
# 强制 HTTPS：代理声明原始协议为 http 时返回 301
ENFORCE_HTTPS=true
LOG_LEVEL=info

JWT_SECRET=<随机生成的长字符串，可用 openssl rand -hex 32>
# 生产环境若长度不足 32 位或仍是示例值，服务会拒绝启动

# 留空则使用本地文件存储（落在 appdata 数据卷，容器重建不丢）
MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/campuspilot
# 未提供 MONGODB_URI 时必须显式置为 true，否则生产模式会拒绝启动
ALLOW_FILE_STORAGE=false

# AI 能力（切换厂商只改 AI_PROVIDER 一行，baseUrl/model 自动套用预设）
# 可选值：deepseek / qwen / zhipu / moonshot / openai / ollama
AI_PROVIDER=deepseek
AI_API_KEY=sk-xxxxxxxx
# 以下两项留空即用预设；切勿写死某一家厂商的地址，否则切换 AI_PROVIDER 会指向错误网关
# AI_BASE_URL=
# AI_MODEL=
```

Key 申请入口：

| 厂商 | AI_PROVIDER | 申请地址 |
| --- | --- | --- |
| DeepSeek | `deepseek` | https://platform.deepseek.com/api_keys |
| 通义千问（阿里云百炼） | `qwen` | https://bailian.console.aliyun.com/ |
| 智谱 GLM | `zhipu` | https://open.bigmodel.cn/usercenter/apikeys |
| 月之暗面 Kimi | `moonshot` | https://platform.moonshot.cn/console/api-keys |

填好后重启服务，用自检接口确认是否真正连通：

```bash
curl http://127.0.0.1:3001/api/ai/status
```

`mode` 为 `remote` 表示已接通；为 `remote-error` 时 `message` 会给出具体原因（Key 无效 / 余额不足 / 模型名不存在等）。

> 注意探针地址用 `127.0.0.1:3001` 直连应用容器，不要走 Nginx 的 80 端口 —— 那里只做 HTTPS 跳转，证明不了应用是否可用。

## 六、启动服务

推荐用一键脚本，它会完成安装 Docker、生成 `.env`、放行端口、构建启动、健康检查与（可选）HTTPS 签发：

```bash
# 仅 HTTP（用 IP 访问）
sudo bash deploy/deploy.sh

# 部署并自动签发证书（域名需先解析到本机）
sudo bash deploy/deploy.sh campus.example.com me@example.com
```

也可以手动执行：

```bash
docker compose up -d --build

# 查看状态
docker compose ps
docker compose logs -f app
```

验证（直连应用容器，避免命中 Nginx 的跳转）：

```bash
curl http://127.0.0.1:3001/api/health
curl http://127.0.0.1:3001/api/health/ready
```

浏览器访问站点地址，首次使用请点击「注册」创建账号：

```text
邮箱：你的邮箱
密码：至少 8 位
```

注册后工作台为空，总览页会提供「一键导入示例数据」入口，用于快速确认部署链路完整可用。

## 七、配置 HTTPS 强制跳转

项目提供**两层**强制跳转，任一层失效都不会放行明文请求：

| 层 | 位置 | 行为 |
| --- | --- | --- |
| Nginx | `deploy/nginx.conf` | 80 端口只保留 ACME 校验路径，其余一律 `301` 跳转；443 承载全部业务 |
| 应用 | `server/middleware/security.js` | 读取代理注入的 `X-Forwarded-Proto`，为 `http` 时返回 `301` |

应用层刻意做了三处收敛，避免误伤：只认代理注入的头（本地直连与 CI 探针不受影响）、探针路径 `/api/health` 与 `/api/health/ready` 豁免（平台健康检查不会被 301 判为异常）、已声明 `https` 不再二次跳转（杜绝代理与应用互跳死循环）。

### 1. 一键签发（推荐）

```bash
# 前提：域名已解析到本机，且云服务器安全组已放行 80 / 443
sudo bash deploy/setup-https.sh campus.example.com me@example.com
```

脚本会依次完成：校验域名解析 → 安装 certbot → 替换 `deploy/nginx.conf` 中的占位域名 → 以临时配置启动 Nginx → 签发证书 → 还原正式配置并重载 → 写入续期钩子 → 验证 301 与证书有效期。

也可以用一条命令把「部署 + 签发」一起做完：

```bash
sudo bash deploy/deploy.sh campus.example.com me@example.com
```

### 2. 为什么用 webroot 而不是 `certbot --nginx`

本站的 Nginx 运行在**容器内**，而 `certbot --nginx` 插件只能改写**宿主机**上的 Nginx 配置，在容器化部署下会失效。因此让 certbot 以 webroot 方式把校验文件写入 `/var/www/certbot`，由容器内的 Nginx 对外提供该文件：

```nginx
location /.well-known/acme-challenge/ { root /var/www/certbot; }
```

对应地，`docker-compose.yml` 已将宿主机的 `/var/www/certbot` 与 `/etc/letsencrypt` 只读挂载进容器。

### 3. 为什么分三个阶段启动 Nginx

443 段依赖证书文件，而证书尚未签发时 Nginx 会因找不到证书启动失败，健康检查失败也就无法响应 ACME 校验 —— 形成死锁。脚本先写入一份「仅 80 端口」的临时配置启动容器，签发完成后再还原正式配置，且失败路径通过 `trap` 保证一定还原。

### 4. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ENFORCE_HTTPS` | 生产环境 `true` | 置为 `false` 可关闭应用层跳转（正常情况下不需要） |
| `TRUST_PROXY` | 生产环境 `true` | 必须为 `true`，否则限流会把所有请求算到代理 IP 上 |

### 5. 验证

```bash
# 明文请求应返回 301，Location 指向 https
curl -sI http://campus.example.com/api/health | head -3

# HTTPS 请求应返回 200
curl -s -o /dev/null -w '%{http_code}\n' https://campus.example.com/api/health/ready

# 确认 HSTS 已下发（浏览器会记住后续必须走 HTTPS）
curl -sI https://campus.example.com/ | grep -i strict-transport-security

# 查看证书有效期
openssl x509 -enddate -noout -in /etc/letsencrypt/live/campus.example.com/fullchain.pem
```

### 6. 自动续期

certbot 的 systemd 定时器负责续期，脚本已写入续期后自动重载容器内 Nginx 的钩子：

```bash
/etc/letsencrypt/renewal-hooks/deploy/reload-campuspilot-nginx.sh
```

可用 `sudo certbot renew --dry-run` 演练一次。

### 7. HSTS 注意事项

`max-age=15552000`（180 天）一旦被浏览器记录，回退到 HTTP 会在有效期内不可访问。首次上线建议先把 `deploy/nginx.conf` 与 `helmet` 配置中的 `max-age` 调小（如 300）验证无误后再调大；`preload` 需确认所有子域均可提供 HTTPS 后再开启。

### 8. 纯 IP 访问

没有域名时无法签发受信任证书，`deploy.sh` 会以 HTTP 模式部署并给出提示。此种情况下域名相关步骤全部跳过，站点仍可正常使用。

## 九、常见问题

| 现象 | 排查方向 |
| --- | --- |
| 打开页面 502 | `docker compose logs app` 查看应用是否启动失败 |
| 容器反复重启、日志提示「生产环境配置校验未通过」 | `.env` 缺失 `JWT_SECRET`（需 ≥32 位）或未配置 `MONGODB_URI` 且未开 `ALLOW_FILE_STORAGE=true` |
| 接口返回 401 | Token 过期或 `JWT_SECRET` 被更换，重新登录即可 |
| 上传大文件失败 | 调整 `client_max_body_size` 与 `MAX_UPLOAD_SIZE` |
| 数据重启后丢失 | 未配置 `MONGODB_URI` 时数据存在容器卷 `appdata` 中，请勿执行 `docker compose down -v` |
| AI 回复是模板文本 | 未配置 `AI_API_KEY`，配置后重启即可切换为真实模型 |
| 浏览器一直跳转、报「重定向次数过多」 | 代理未注入 `X-Forwarded-Proto`（检查 Nginx 的 `proxy_set_header`），或 `CLIENT_URL` 与实际协议不一致 |
| certbot 报 `Connection refused` / 校验失败 | 域名未解析到本机、安全组未放行 80 端口，或临时配置阶段 Nginx 未启动（`docker compose logs nginx`） |
| 证书签发成功但浏览器仍提示不安全 | 未重载 Nginx：`docker compose exec nginx nginx -s reload` |
| 健康检查被判定为异常 | 平台探针应指向 `/api/health` 或 `/api/health/ready`（已豁免跳转），不要用站点根路径 |

## 十、零成本方案：本机 + 内网穿透

如果暂时不买服务器，可以用 Cloudflare Tunnel 把本机服务映射到公网，适合答辩演示与作品集展示。

### 1. 以生产模式启动（单进程同时提供前端与 API）

```bash
npm run build
# .env 中设置 NODE_ENV=production
npm start
# 本机访问 http://localhost:3001
```

### 2. 下载并启动隧道

```powershell
# Windows
Invoke-WebRequest -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile "$env:TEMP\cloudflared.exe"
& "$env:TEMP\cloudflared.exe" tunnel --url http://localhost:3001 --no-autoupdate
```

```bash
# Linux / macOS
curl -fsSL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o cloudflared
chmod +x cloudflared
./cloudflared tunnel --url http://localhost:3001 --no-autoupdate
```

命令输出中会出现形如 `https://xxxx-xxxx-xxxx.trycloudflare.com` 的公网地址，任何人可直接访问。

### 3. 验证

```bash
curl https://xxxx-xxxx-xxxx.trycloudflare.com/api/health
```

### 注意事项

| 事项 | 说明 |
| --- | --- |
| 地址会变 | 免费快速隧道每次重启都会生成新的随机域名，演示前记得重新获取 |
| 电脑必须开机 | 隧道依赖本机进程，关机即下线 |
| 数据库 | 数据存在本机 `server/data/db.json`，备份该文件即可迁移 |
| 稳定性 | 免费隧道无可用性保证，正式对外提供服务仍建议购买云服务器 |
| 演示完成后 | 按 Ctrl+C 关闭隧道进程，服务随即下线 |

## 十一、性能与安全建议

1. 生产环境将 `JWT_SECRET` 设置为强随机值，并定期轮换
2. 上传目录不要放在公开可执行路径下，本项目已限制文件扩展名白名单
3. 数据库开启 IP 白名单，只允许服务器访问
4. 为 Nginx 增加限流配置，防止接口被刷
5. 使用 `docker compose` 的 `restart: unless-stopped` 保证进程异常后自动拉起
